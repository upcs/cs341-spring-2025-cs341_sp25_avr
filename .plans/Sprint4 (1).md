## Develop!

- Functional completeness, your goal is to deploy a release candidate version!
- This means you finalize any incomplete features
- Document any known bugs/issues
- Create a set of story acceptance tests focusing on the UI
- Test each of these on 3 desktop web browsers, and one mobile browser • Document problems
- Add performance testing code and report the time it takes to completely display your main page (your primary data visualization page).
- Create a deployment build • Write a script to deploy (install) your software.
- Monetization: Does your app have a source of revenue?
- You should add ads or have a subscription link setup (or other appropriate feature)
- Test functions for each feature.
- Graceful error handling (i.e. mismatched tags shouldn’t break your beautiful display)
- Continued focus on your team’s project goals (Security, Aesthetics, Performance, etc.)

## Submission

The “submission” of your code will be the most recent version of your software (on Github) prior the start of class on the last day of the sprint. Your instructor will check to see that Travis-CI is in a successful build state, your code may be cloned by your instructor and tested for the functionality requested. It is highly recommended that you include a summary of completed features (and if necessary how to use them), in your top level README file.

## GitHub

- All bugs should be fixed and issues closed on github
- All branches should be merged into the main
- All branches (other main) closed and deleted
- All code commented and uniformly formatted
- All unused code removed from the repo
- All password files/information and sensitive information redacted from repo

## Grading

Multiple git pushes by all team members.  
Minimum requested features implemented including test functions  
Additional features implemented as time permitted including test functions  
Correct and complete use of Trello  
CI on pull requests & code coverage integration is active
